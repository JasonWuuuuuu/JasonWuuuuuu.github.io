开篇 · 我为什么开始写这个博客

伍海洋 Haiyang Wu · ⏱ 约 5 分钟阅读

作为一个从电气工程"跨界"到交通运输的博士生，我常常被问到一个问题： "你一个学强电的，怎么跑去搞交通了？" 每次回答都略显仓促。开这个博客，一半是想给自己一个把想法写下来的地方， 另一半也是想把那些"仓促的回答"慢慢写完整。

为什么开始写？

读博之后我才发现一件事：研究做得越多，能讲清楚的人反而越少。 论文写得很正式，但那些"为什么走这条路"、"哪里卡了三个月"、"为什么放弃了第一个方案"的故事， 全都被压成了一行 acknowledgement。可恰恰是这些被压扁的部分，才是真正能帮到别人的东西。

所以我想，与其把这些笔记留在 Obsidian 的某个角落里发霉，不如放到一个公开的地方—— 哪怕只有一个人在搜索时偶然点进来，看到我说"这个问题我也踩过坑"，也算值了。

写作不是把已经想清楚的事情抄下来，而是想清楚一件事的过程本身。

—— 某个我现在想不起来是谁的人，但这话我一直记着

我打算写些什么？

大致会是这么几类内容：

  • 研究笔记 — 换道交互建模、因果推断、轨迹规划这些方向的方法梳理与踩坑记录。
  • 工程实战 — 边缘部署、设备选型、算法落地时遇到的真实问题，能复现就尽量复现。
  • 论文阅读 — 读到值得记一笔的论文，写一两段自己的理解。
  • 博士生活 — 一些非技术的东西：时间管理、心态、和导师的沟通，可能还有一些书评。

代码块

下面是一段 Python 代码示例（一个最简单的车跟驰模型）：

import numpy as np

def krauss(v: float, v_desired: float, dt: float, a_max: float = 1.5) -> float:
    """最朴素的跟驰速度更新。"""
    # 加速到期望速度，但不超过最大加速度
    if v < v_desired:
        v_next = min(v + a_max * dt, v_desired)
    else:
        v_next = max(v - a_max * dt, v_desired)
    return max(0.0, v_next)

# 模拟 10 秒
v, t = 0.0, 0.0
while t < 10.0:
    v = krauss(v, v_desired=20.0, dt=0.1)
    print(f"t={t:.1f}s  v={v:.2f} m/s")
    t += 0.1
